# SPI Sistematización — web app (Firebase + Gemini)

Web app where SPI analysts load product folders in batches, Gemini on Vertex AI extracts the
planilla, the analyst reviews it screen by screen and resolves decisions, and the approved
planilla feeds the InvimÁgil Inyector extension. Replaces the Windows install of InvimÁgil Base
for day-to-day work; the extractor core (schema, prompt, catalog, Excel writer) is shared.

```
web/        React + Vite + TypeScript, Firebase JS SDK. Hosting.
functions/  Python 2nd gen Cloud Functions: extraer_tramite, aplicar_decisiones, exportar_excel.
  spi/      gemini.py (Vertex AI call, schema mode with text-mode fallback), dossier.py (Storage -> parts)
  nucleo/   copy of extractor/invimagil_base + recursos (generated by scripts/sync-nucleo.sh, gitignored)
scripts/    sync-nucleo.sh, emuladores.sh, seed-emulador.mjs
firestore.rules, storage.rules, firebase.json
```

## Flow and states

`cargando → cargado → extrayendo → en_revision → aprobado → inyectado → enviado → cumple | no_cumple`
(plus `error`, `archivado`). The web app moves the human steps; the functions own extraction.

- **Nuevo lote**: drag one or more product folders. Each folder becomes a trámite. Same ignore
  rules as the CLI (`_invimagil`, `NO USAR…`, old `MAESTRO NSO` files). Extraction is queued two
  at a time in the browser; state lives in Firestore.
- **Extraction**: PDFs and images go to Gemini by `gs://` reference (no rasterising), Word/Excel
  as text. Output is validated against `invimagil-catalogos.txt` exactly as in the CLI.
- **Review**: one tab per InvimÁgil step, source note per field, decisions highlighted. Answers go
  through `aplicar_decisiones` and create a new planilla version (`tramites/{id}/planillas/v{n}`).
- **NSO vigente**: number, dates and InvimÁgil request id are entered per trámite (the extractor
  does not produce them); `planilla.json para la extensión` adds them as `sistematizacion.*`, which
  `extension/mapa-formulario.json` maps to the Sistematización screen.
- **Audit**: every action writes `tramites/{id}/eventos`.

Access: Google sign-in or email + password (self sign-up with email verification and password reset),
and only emails listed in `usuarios/{email}` with `activo: true`. Rules and functions both require
`email_verified`, so a password account cannot work until its address is confirmed.
Admins (`rol: admin`) manage users. Planillas and generated files are written only by the functions.

## Local development (emulators, no cloud)

Needs Node 20+, Python 3.13, Firebase CLI, Java 11+ (`brew install openjdk@21`).

```bash
cd app/functions && python3.13 -m venv venv && ./venv/bin/pip install -r requirements.txt
cd ../web && npm install
```

```bash
app/scripts/emuladores.sh            # Auth, Firestore, Storage, Functions, UI on :4000
node app/scripts/seed-emulador.mjs   # test accounts + one client (run after each emulator start)
npm --prefix app/web run dev         # http://localhost:5173, "Entrar (emulador)"
```

- `functions/.env.local` (gitignored) with `INVIMAGIL_SIMULAR=<path to a planilla.json>` skips
  Gemini and returns that planilla: use it for UI work.
- Without it, the emulated functions call the real Vertex AI with your gcloud Application Default
  Credentials and a real project in `GOOGLE_CLOUD_PROJECT`; the demo project cannot.
- macOS: `emuladores.sh` exports `no_proxy=*`. Without it the Python worker crashes on fork
  (objc "initialize ... fork()" error) and callables fail with "socket hang up".

## Deploy to a real project

1. Create the Firebase project on the **Blaze** plan. Firestore in **southamerica-east1**
   (same region as the functions, see `REGION` in `functions/main.py` and `web/src/lib/firebase.ts`).
   Enable Storage and Authentication → Google and Email/Password providers.
2. Google Cloud console of the same project: enable the **Vertex AI API**. Give the functions'
   runtime service account (default compute service account) the role **Vertex AI User**.
3. Check the model id in Vertex AI Model Garden and set it in `functions/.env`
   (`GEMINI_MODEL`, `GEMINI_LOCATION`). The default is `gemini-3.1-pro-preview` on `global`.
4. `cd app && firebase use --add <project-id>`.
5. `cp web/.env.production.example web/.env.production.local` and fill it from
   Firebase console → Project settings → Your apps (web).
6. In Firestore, create `usuarios/<your google email>` with `{nombre, rol: "admin", activo: true}`.
7. `firebase deploy` (predeploy syncs the extractor core and builds the web app).

Gemini reads the dossier PDFs straight from the project's bucket. If extraction fails with a
permission error on `gs://…`, grant the Vertex AI service agent
(`service-<project-number>@gcp-sa-aiplatform.iam.gserviceaccount.com`) **Storage Object Viewer**
on the bucket.
